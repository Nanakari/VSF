# 功能契约

本文记录当前实现的边界和验收标准；操作示例见 [README](../README.md)。

| --- | --- | --- | --- | --- |

| 更新线上检索数据 | 索引结束自动同步；也可用导入脚本 | — | 索引/删除后自动同步，也可独立同步 | 令牌保护的同步 API |

## 频道生命周期

- 增加频道：URL、handle、ID 最终都解析到 YouTube 返回的频道 ID，以该 ID 去重。标准 `@handle` 链接直接调用 API；重复添加会继续更新已有频道。配额错误保留原有错误类型，不误报“频道不存在”。
- 更新频道：频道卡片提供“增量更新”和“历史回填”，使用频道 ID 操作；回填按钮沿用游标，不自动重置。空频道可以正常标记回填完成，缺少发布日期时按视频 ID 恢复游标。
- 删除频道：完整名称确认；写事务内再次核对名称并清理视频、歌曲、时间点和两类扫描状态。失败整体回滚；重新增加同一频道时从干净状态开始。未配置站点时允许本地删除，部分配置则在删除前拒绝。
- 站点同步：配置完整时在本地操作完成后执行；失败保留本地结果，频道列表仍刷新。“立即同步站点”只同步现有数据库，不要求 YouTube Key，也不重新索引或重复删除。

索引、删除和独立同步在设置服务内共用任务互斥，运行期间禁止覆盖站点配置。线程启动失败释放任务状态；轮询请求失败后自动重试，旧轮询响应不能解除新任务的提交锁定。配额中断保留已完成计数与视频重试状态。

## 索引模式

| 模式 | 遍历边界 | `max_videos` 的含义 | 下次运行 |
| --- | --- | --- | --- |
| `index-channel` / 页面“full” | 从最新上传开始 | 检查最近 N 条上传 | 重新从最新位置扫描；已经完成的视频跳过 |
| `update-channel` / “incremental” | 本轮开始时保存的本地最新发布时间；边界同时间的视频也检查 | 上传遍历阶段最多 N 条新发现或需要执行的记录 | 未走完窗口则保留原始边界；已处理记录不重复占额度 |
| `backfill-channel` / “backfill” | 保存的历史游标之后，直到上传列表末尾 | 游标后最多 N 条上传 | 从游标继续；`--reset` 可重新开始 |

三种频道模式都会先处理到期的重试/复查队列，该队列独立取最多 N 条，所以 `max_videos` 不是整次任务的 YouTube 请求上限。一次视频处理也可能需要多个 API 请求。

待处理队列也包含中断后仅完成发现的 `discovered` 记录；启用“不按歌回标题过滤”时包含历史 `filtered` 记录，避免它们因早于增量日期边界而永久漏扫。收紧过滤条件不会把已成功索引的视频退回 `filtered`，反复切换开关不会重复抓取已经完成的评论。同一次任务中重试与上传列表重合的视频只计一次扫描。

未变化的视频元数据保留导出时间戳；重复时间轴保留歌曲和时间点 ID，仅更新实际变化的内容并移除失效条目。“新增时间点”只计新插入的记录，相同内容重复索引不会制造额外同步变更。

增量模式下，新发现的非歌回视频首次记录为 `filtered`，仍计一次发现额度；后续运行中仍不符合标题条件的已知视频不占额度。启用“包括所有视频”或视频标题改为歌回后，该记录重新获得处理资格，并正常计入额度。只有走到旧边界或列表末尾才清除增量窗口。

页面默认增量更新、每批 1000 个视频、每视频 100 条顶层评论。CLI 的普通频道扫描默认 100 个视频，增量和回填默认 1000；评论上限均默认 100。评论按相关性读取，时间轴候选至少需要两条有效歌曲记录，选择其中评分最高的一个评论。

索引状态为 `discovered`、`indexing`、`indexed`、`filtered`、`no_timeline`、`comments_disabled`、`retry`。失败记录保留错误与重试时间，第一次失败可立即重试，连续失败退避上限为 1 小时。没有时间轴的视频常规 7 天复查一次；增量模式对最近 30 天的视频默认每天复查；评论关闭的视频 30 天复查一次。历史回填的单个视频失败不阻塞更旧视频，配额耗尽则结束当前任务。

## 搜索与作者身份

三个搜索条件使用 AND。全部为空时网页显示频道首页；只选频道时按时间点数量排序；指定歌曲时按相关性排序；只选作者时按歌曲标题排序。未指定频道时合并跨频道结果，并保留各频道下的时间点。

频道卡片链接使用稳定的频道 ID。查询值等于已有频道 ID 时只匹配该频道；其他输入按频道名称模糊匹配，保留手工搜索多个相关频道的能力。线上按频道或作者查询复用同一次聚合中的频道计数，不再为同一页重复聚合时间点。

标题支持空白折叠、紧凑写法、版本合并和有限拼写近似。长度不超过 4 的 ASCII 歌曲查询采用完整键或前缀匹配；同长度范围的作者查询要求匹配一个完整作者键。较长作者查询允许规范化后的子串匹配。

作者姓名中的空格不能当作合作作者分隔符。`After the Rain`、`Andy`、`Taylor Swift` 必须保留为完整姓名。`ft.`、`feat.`、`with`、`and` 等合作标记必须匹配单词边界；`/`、`×`、`&`、`+`、`・` 等符号和带空格的 `x` 可分隔合作作者。未知作者不会命中作者筛选，查询副作者时仍返回对应歌曲。`/api/search` 与 `/api/entries` 必须使用相同作者筛选逻辑。

共享验收样例包括：搜索 `Kanaria` 不返回 `After the Rain` 或 `Wanda`；`Andy` 可以精确命中；`Ado × LiSA`、`LiSA・Ado`、`Ado covered by LiSA` 可以按任一作者命中。

线上歌曲列表默认每页 20 组，时间点默认每页 10 条，两者上限均为 50。时间点按发布日期降序、秒数升序、记录 ID 升序排序。

歌曲与频道均展开后才请求时间点；重新折叠/展开复用已加载结果。时间点请求失败时提供独立重试按钮，包括只有一页的结果。清空查询会使未完成的旧查询失效。

## 同步与失败行为

导出包含频道、视频、歌曲分组、歌曲、时间点五张表及内容版本。首次同步或无完整基线时使用完整快照；最多 80 个行操作且估算载荷不超过 1,200,000 字节时可使用补丁；本地版本与成功基线相同则跳过上传。线上副本不应绕过该协议修改，跳过上传时客户端不会额外核对远端内容。

导出在同一个 SQLite 读事务中读取所有表与分组；另一进程并发更新或删除频道不会生成混合版本的快照。

| 情况 | 行为 |
| --- | --- |
| 补丁基线冲突或接口不可用（409 / 404 / 405） | 回退完整快照 |
| 网络失败、权限配置错误、其他服务端错误 | 报错并保留原有本地成功基线 |
| 暂存缺批、过期版本或提交出现外键错误 | 不替换线上数据 |
| 作者补全导致分组键变化 | 原有歌曲、时间点更新引用，与分组变化一起原子提交 |
| 删除提供作者信息的频道导致分组键回退 | 剩余频道记录保留，并在同一事务内迁移引用 |
| 本地索引或删除成功、上传失败 | 本地变更保留，刷新频道列表并报告失败；修复配置后点击“立即同步站点” |

同步 API 需要 `x-seed-token`；缺失或错误令牌返回 404。非法请求通常返回 400，版本或完整性冲突返回 409，提交执行失败返回 500。公开查询失败返回 503；缺少歌曲分组的详情请求返回 400。

## 兼容与发布

本次整理保留所有原有启动命令、端口、环境变量和数据库位置，不需要迁移现有 SQLite 或 D1 表结构。Worker 搜索与补丁修复需要部署更新后的 `dist/` 才会在线上生效；既有快照数据格式仍可使用。

源码测试不消耗 YouTube 配额，也不发布站点。发布时分别确认源码、生成的 Worker、迁移和便携版打包输入属于同一版本。
